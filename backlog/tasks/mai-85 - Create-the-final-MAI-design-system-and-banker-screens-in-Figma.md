## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Replace the unsuccessful Stitch experimentation with a professional, reviewable design source for the final product. Figma is the default tool because it supports design variables, reusable components, interactive prototypes, accessibility review, and developer handoff. Another tool may be selected only through a documented decision showing equal or better support for those outcomes. This task delivers design artifacts and specifications, not production React implementation.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The design tool choice is documented, with Figma as the default and any alternative justified against collaboration, components, variables, prototyping, accessibility, export, and developer-handoff requirements
- [ ] #2 A complete visual foundation defines color, typography, spacing, grid, elevation, iconography, motion, breakpoints, and accessibility tokens
- [ ] #3 A reusable component library covers variants, responsive behavior, validation, loading, empty, error, disabled, permission, and destructive states
- [ ] #4 Final desktop and responsive screens cover dashboard, deals, entities and Target Dossier, agentic workspace, due diligence and engines, negotiation, documents and closing, team, notifications, and settings
- [ ] #5 End-to-end banker flows are represented as interactive prototypes with navigation, happy paths, failure states, and human-approval checkpoints
- [ ] #6 The design explicitly distinguishes real integrated capabilities from unavailable, simulated, or future functionality
- [ ] #7 Developer handoff includes inspectable variables, component anatomy, assets, annotations, content rules, responsive specifications, and mapping to the local component/API contracts
- [ ] #8 Design review records approval and unresolved questions before any task claims final UI implementation
<!-- AC:END -->
