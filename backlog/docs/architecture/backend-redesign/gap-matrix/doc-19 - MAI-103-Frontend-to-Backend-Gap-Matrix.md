## 1. Reading the matrix

The three tables below form one matrix. `ID` is the join key. Every row records the frontend family and route, actor and participant type, visible state and action, protected operation and human boundary, required command/query/read model, bounded context and aggregate, synchronous/asynchronous/event/update mechanism, authorization and isolation, audit/evidence/provenance, concurrency/idempotency, current support, gap, target design, and current implementation disposition.

Abbreviations:

- **H**: authenticated human; **AI**: agent or model output only.
- **H-only**: only an authorized human may cause the transition.
- **HTTP**: ordinary synchronous JSON HTTP; **202 job**: durable asynchronous operation returned as a job reference.
- **Poll**: conditional polling with ETag; **SSE**: one-way progress stream; **None**: no streaming mechanism.
- **T/W/D/O/F**: tenant, workspace, deal, object, and field scope.
- **K/A/RP/RM**: Keep, Adapt, Replace, Remove.
- **Protected 404**: unauthenticated or unauthorized callers receive the same non-disclosing response before protected data is loaded.

Global target rules apply to every row:

1. Resolve authenticated identity, active membership, tenant/workspace scope, purpose, sponsor, expiry, deal relationship, object restriction, and field restriction before repository loading.
2. Every material aggregate write carries `If-Match` and an expected aggregate version. Every retried command carries `Idempotency-Key`.
3. A state change, authorization change, external effect, decision, release, export, archive, or deletion request writes an append-only audit event in the same transaction as domain state and outbox records.
4. AI may read only authorized evidence and may create proposals, recommendations, calculations, plans, and reversible artifacts. AI cannot approve, reject, price, send, waive, sign, invite, offboard, grant, revoke, release, archive, restore, terminate, or delete.
5. Source changes create new versions and targeted dependency invalidation. History is never destructively rewritten.

## 5. Coverage and accepted MAI-102 deviations

The matrix covers the 25 screen families in the MAI-102 authority matrix plus the shell, all canonical route modes, banker/administrator/deal-team/counsel/investment-committee/approver/sponsor/external-participant actors, and every workflow named in MAI-103.

Accepted MAI-102 visual deviations do not change backend semantics:

- MAI-100 responsive compositions outside the Decision Room are implementation-owned governed runtime derivations.

- All backend behavior shown by current MAI-99/100/101 screens remains explicitly fixture-backed.

## 6. Gap conclusion

The existing backend supplies useful validation, pagination, optimistic-version examples, provider seams, deterministic engines, and test evidence. It does not supply the approved product’s identity, tenancy, authorization, semantic workflow, immutable decision, evidence/provenance, durable job, audit, external-participant, or release boundaries. The target therefore adapts reusable primitives and algorithms but replaces the mock-backed route/store and current PostgreSQL domain shape rather than preserving them for compatibility.
