## Governed multi-subagent execution

Act as the authoritative task coordinator.

Read and follow `prompts/SUBAGENT_RULES.md`.

Use parallel subagents when the approved task plan contains disjoint
investigation, implementation, test, review, or verification slices.

Every subagent must receive a concrete `/goal` as its first substantive
instruction. The `/goal` must define the exact outcome, exclusive paths,
forbidden shared paths, required checks, return artifact, and stop conditions.

Before spawning writing subagents:

1. record the slice/file-ownership matrix;
2. reserve shared and integration files for yourself;
3. ensure writing ownership is disjoint;
4. define integration order and slice-level verification.

Writing subagents must use isolated scratch worktrees or patch-only handoffs.
Never permit concurrent writes to this authoritative task worktree.

Integrate accepted subagent work serially into this task branch. Maintain one
Backlog writer, one authoritative branch, one task PR, and one task-wide
verification result.

Do not use subagents when the work cannot be safely separated.
